Selenium WebDriver Architecture:
--------------------------------
Java test code acts as the client, and Selenium language bindings act as the client library.
When the test is triggered, Selenium converts the WebDriver commands into HTTP requests formatted according to the W3C WebDriver protocol (earlier it was JSON Wire Protocol).
These HTTP requests are sent to the browser driver (like ChromeDriver or GeckoDriver), which acts as the server.
The browser driver interprets the request and communicates with the actual browser using browser-specific mechanisms to execute the command (click, type, navigate, etc.).
After execution, the browser sends the result back to the browser driver, which converts it into an HTTP response and sends it back to the Selenium client library.
Finally, the response is returned to the Java test code as success or an exception.

CSS Selector quick summary (Selenium)

#id                 -> element with id
.class              -> element with class
tag                 -> by tag name
tag.class           -> tag with class
tag#id              -> tag with id

tag[attr='value']   -> exact attribute match
tag[attr*='val']    -> attribute contains
tag[attr^='val']    -> attribute starts with
tag[attr$='val']    -> attribute ends with

A B                 -> B inside A (descendant)
A > B               -> B direct child of A
A + B               -> B immediately after A (adjacent sibling)
A ~ B               -> B after A (general sibling)

:nth-child(n)       -> nth child (counts all child nodes)
:nth-of-type(n)     -> nth element of same tag type

Examples:
#username
input[name='email']
button.btn.primary
form#login input[type='password']
div[id^
::contentReference[oaicite:0]{index=0}
Note: cssSelector doesn't support backward traversing,text and indexing

-xpath: path of element on html tree.
------
XPath quick summary (Selenium)
Absolute xpath: refers to the path of element right from root node to destination element, we use '/' while writing xpath
Relative xpath: path of element any node(any descendent),we use '//' while writing xpath

Basic:
 //tag                    -> all matching tags anywhere
 //*                       -> any tag
 //tag[@attr='value']      -> attribute equals
 //tag[text()='value']     -> exact text match
 //tag[contains(text(),'x')]-> text contains

Attribute contains/starts-with:
 //tag[contains(@attr,'x')]    -> attribute contains
 //tag[starts-with(@attr,'x')] -> attribute starts with

Indexing:
 (//tag)[1]               -> first match (1-based index)
 //tag[@x='y'][2]          -> 2nd matching sibling at same level

Logical operators:
 //tag[@a='1' and @b='2']  -> AND
 //tag[@a='1' or  @b='2']  -> OR
 //tag[not(@disabled)]     -> NOT

Axes (very useful):
 //a/b                     -> direct child b of a
 //a//b                    -> any descendant b of a
 //tag/parent::p           -> parent
 //tag/ancestor::div       -> any ancestor div
 //tag/child::span         -> direct child span
 //tag/following-sibling::td -> following sibling td
 //tag/preceding-sibling::td -> preceding sibling td

Common stable patterns:
 //*[@id='username']
 //input[@name='email']
 //button[contains(@class,'submit')]
 //label[.='Email']/following-sibling::input
 //div[@data-testid='login-button']

Notes:
 - XPath index starts at 1.
 - Use parentheses for global indexing: (//div[@class='x'])[2]
 - we can join xpath using | (pipeline operator), to identify more than one element in different node of html tree
 - Group index in xpath --> Retrieving one element from a group of matching elements by using index.

-Advanced xpath:
-starts-with() --> replacement for conatins() -->//[starts-with(text(),'actiTime')]
contains()     -> matches if the text/attribute contains the substring anywhere
starts-with()  -> matches only if the text/attribute begins with the substring

Independent & Dependent XPath
-----------------------------
Concept:
- Used to build stable locators when:
  1) A unique/identifiable element is nearby (Independent / Anchor)
  2) The element you want is related to it (Dependent / Target)
- Find the independent element first, then move to the dependent element using XPath axes:
  following-sibling, preceding-sibling, ancestor, descendant, etc.

Independent XPath (Anchor):
- Stable reference element (ex: name/label that rarely changes)
  //td[text()='John']

Dependent XPath (Target):
- Locate target element relative to the anchor

Example: Checkbox for a specific row
- Independent: cell containing the name
  //td[text()='John']

- Dependent: checkbox in the same row (relative to the name cell)
  //td[text()='John']/preceding-sibling::td//input[@type='checkbox']

When ".." is used in XPath:

- ".." means parent of the current node.

Examples:
1) Child -> Parent
   //input[@id='username']/..

2) Move up multiple levels
   //input[@id='username']/../../..

3) Go up, then down to related element
   //label[text()='Username']/../input

4) Independent -> parent row -> target element in same row
   //td[text()='John']/..//input[@type='checkbox']

Note:
- /.. is same as /parent::*

-XPath last() 

Meaning:
- last() returns the position of the last node in the current node set.
- Used to select the last (or relative-to-last) matching element.

Syntax:
  (//tag[condition])[last()]
  (//tag[condition])[last()-1]   -> second last
  (//tag[condition])[position() < last()] -> all except last

Examples:
1) Last row of a table
   (//table/tbody/tr)[last()]

2) Last button on the page
   (//button)[last()]

3) Last checkbox in a list
   (//input[@type='checkbox'])[last()]  -->braces ie first internally it executes xpath first then sotre the result in xpath array, then using last() function we retrieve last element present in xpath array.

4) Second last element
   (//a[contains(text(),'Edit')])[last()-1]

Note:
- last() works with the CURRENT matched set (after applying your conditions).
- XPath index starts at 1.

-XPath position()

Meaning:
- position() returns the index (1-based) of the current node within the selected node set.
- Used for selecting elements by order, ranges, or patterns (odd/even).

Common uses:

1) Select a specific index (same effect as [n])
   (//button)[position()=3]

2) Select first 3 elements
   (//tr)[position()<=3]

3) Select elements from 2 to 5
   (//tr)[position()>=2 and position()<=5]

4) Select all except first
   (//li)[position()>1]

5) Select odd/even elements
   (//li)[position() mod 2 = 1]   -> odd
   (//li)[position() mod 2 = 0]   -> even

Notes:
- position() is 1-based (first element is position()=1).
- It works on the CURRENT node set produced by your XPath.
- [3] is shorthand for [position()=3].

-XPath Axes

Meaning:
- Axes define the direction to navigate in the DOM relative to the current node.

Most-used axes with syntax + example:

1) child::        -> direct children -->immediate child element, represented with /(used in deriving absolute xpath)
   //div[@id='box']/child::input

2) descendant::   -> any level inside (children, grand-children...) --> traverses any child, using //(relative xpath)
   //div[@id='box']/descendant::a

3) parent::       -> direct parent -->traverses to immediate parent element --> /.. (shortcut)
   //input[@id='username']/parent::div

4) ancestor::     -> any parent up the tree
   //input[@id='username']/ancestor::form

5) following-sibling:: -> next siblings (same parent) after current node (downward direction)
   //td[text()='John']/following-sibling::td

6) preceding-sibling:: -> previous siblings (same parent) before current node (upward direction)
   //td[text()='John']/preceding-sibling::td

7) following::    -> all nodes after current node in document order
   //h2[text()='Users']/following::a[1]

8) preceding::    -> all nodes before current node in document order
   //input[@id='pwd']/preceding::label[1]

9) self::         -> current node itself
   //button[@id='save']/self::button

10) descendant-or-self:: -> current node + all descendants
    //div[@id='menu']/descendant-or-self::a

Quick notes:
- sibling axes stay on the same level (same parent).
- following/preceding can cross levels (broader than siblings).
- Use axes for Independent(Anchor) + Dependent(Target) XPath.

WHAT IS CHROMEOPTIONS?
---------------------
ChromeOptions is a Selenium class used to customize how the Chrome browser is launched.
It helps in:
- Running browser in headless mode
- Disabling notifications
- Running in incognito
- Setting download preferences
- Handling SSL errors
- Adding extensions
- Passing Chrome arguments
----------------------------------------
BASIC SYNTAX
----------------------------------------
ChromeOptions options = new ChromeOptions();
WebDriver driver = new ChromeDriver(options);
----------------------------------------
COMMONLY USED OPTIONS (IMPORTANT)
----------------------------------------
1) HEADLESS MODE
----------------
Runs browser without UI (used in CI/CD)
options.addArguments("--headless=new");
----------------------------------------
2) MAXIMIZE BROWSER
-------------------
options.addArguments("--start-maximized");
----------------------------------------
3) INCOGNITO MODE
-----------------
options.addArguments("--incognito");
----------------------------------------
4) DISABLE NOTIFICATIONS
------------------------
options.addArguments("--disable-notifications");
----------------------------------------
5) DISABLE INFOBARS
-------------------
options.addArguments("--disable-infobars");
----------------------------------------
6) DISABLE EXTENSIONS
---------------------
options.addArguments("--disable-extensions");
----------------------------------------
7) IGNORE SSL CERTIFICATE ERRORS
--------------------------------
options.addArguments("--ignore-certificate-errors");
----------------------------------------
8) DISABLE POPUPS
-----------------
options.addArguments("--disable-popup-blocking");

        DesiredCapabilities caps = new DesiredCapabilities();

        caps.setBrowserName("chrome");

    }

Synchronization:
----------------
Matching speed of selenium with the speed of application is called as synchronization.: implicit wait,explicit wait,Thread.sleep(),Fluent wait
--Implicit Wait : will handle the synchronization of findElement() and findElements(). implicitlyWait() takes 2 arguments of type long(waiting time) and TimeUnit(time unit-->DAYS,HOURS,MINUTES,SECONDS,MILISECONDS...).
                  driver.manage().timeouts().implicitlyWait(time, TimeUnit.SECONDS);
				  driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));    //Preffered
                  When Selenium encounters findElement() or findElements(), it first checks element presence. If implicit wait is defined, it keeps polling the DOM every 500ms until the timeout expires; otherwise, 
                  it immediately throws an exception or returns an empty list
--Explicit Wait : used to handle synchronization of any methods including findElement() and findElements(),WebDriverWait class is called as explicit wait which takes 2 arguments of type WebDriver and long,
                  default time unit is seconds.During runtime, Explicit Wait continuously checks the specified condition at regular intervals of 500 millisecondsuntil the condition becomes true or the timeout expires, 
                  after which Selenium throws a TimeoutException.All the methods present in ExpectedConditions class are called as Predicates
				  WebDriverWait wait = new WebDriverWait(driver,Duration.ofSeconds(10));
				  wait.until(ExpectedConditions.visibilityOf(element));
				  Note:Refer all Expected Conditions
					+----+----------------------------------------------+------------------------------------------------------------+------------------------+
					| #  | ExpectedCondition                             | When to use                                                 | If not satisfied       |
					+----+----------------------------------------------+------------------------------------------------------------+------------------------+
					| 1  | visibilityOfElementLocated(By)                | Element must be present + visible                           | TimeoutException       |
					| 2  | presenceOfElementLocated(By)                  | Element only needs to be in DOM (may be hidden)             | TimeoutException       |
					| 3  | elementToBeClickable(By/WebElement)           | Element should be visible + enabled (ready to click)        | TimeoutException       |
					| 4  | invisibilityOfElementLocated(By)              | Wait for loader/spinner/element to disappear                | TimeoutException       |
					| 5  | textToBePresentInElementLocated(By, text)     | Wait until element text contains expected text              | TimeoutException       |
					| 6  | textToBePresentInElementValue(By, text)       | Wait until input/value attribute contains expected text     | TimeoutException       |
					| 7  | titleContains(text) / titleIs(text)           | Wait until page title contains/is expected title            | TimeoutException       |
					| 8  | urlContains(text) / urlToBe(url) / urlMatches | Wait until URL contains/is/matches expected URL             | TimeoutException       |
					| 9  | frameToBeAvailableAndSwitchToIt(By/int/String)| Wait for frame/iframe and switch into it                    | TimeoutException       |
					| 10 | alertIsPresent()                              | Wait until alert popup appears                              | TimeoutException       |
					| 11 | numberOfElementsToBeMoreThan(By, n)           | Wait until list size > n (autosuggest, results, table rows) | TimeoutException       |
					| 12 | numberOfElementsToBe(By, n)                   | Wait until list size == n                                   | TimeoutException       |
					| 13 | elementSelectionStateToBe(By, true/false)     | Wait until checkbox/radio selection state is as expected    | TimeoutException       |
					| 14 | stalenessOf(WebElement)                       | Wait until old element is detached (re-render/refresh)      | TimeoutException       |
					+----+----------------------------------------------+------------------------------------------------------------+------------------------+
Note:- For Explicit Wait, if the condition is not met within the wait time, Selenium throws TimeoutException.
		  
--Fluent wait:    The fluent wait is used to tell the web driver to wait for a condition, as well as the frequency with which we want to check the condition before throwing an "ElementNotVisibleException" exception.
                  Fluent Wait allows maximum wait time, polling interval, and ignored exceptions to be customized, making it suitable for highly dynamic elements.
                  Wait<WebDriver> wait = new FluentWait<WebDriver>(driver)       //Creates a FluentWait instance using WebDriver reference
                                        .withTimeout(Duration.ofSeconds(20))     //Maximum time Selenium should wait
                                        .pollingEvery(Duration.ofSeconds(2))     //Selenium checks condition every 2 seconds,Default polling = 500 ms
                                        .ignoring(NoSuchElementException.class); //Ignores exception during polling,Prevents test from failing immediately
				  WebElement element = wait.until(driver ->driver.findElement(By.id("username")));
				  When Fluent Wait is REALLY used
                  ✔ Highly dynamic elements
                  ✔ Irregular loading behavior
                  ✔ Need to ignore specific exceptions



| Feature            | Implicit | Explicit | Fluent |
| ------------------ | -------- | -------- | ------ |
| Specific element   | ❌        | ✅        | ✅  |
| Specific condition | ❌        | ✅        | ✅  |
| Readable           | ✅        | ✅        | ❌  |
| Maintainable       | ❌        | ✅        | ❌  |
| Real projects      | ❌        | ✅        | Rare  |
Implicit wait is not preferred because it applies globally and causes delays, while Fluent wait is complex and rarely needed. Explicit wait is mostly used because it is precise, flexible, and reliable.
Don't mix Implicit Wait + Explicit Wait-->Selenium adds both waits together internally,Causes unpredictable delays.

--Page Object Model: It is page factory design patterns. It is Java design pattern, used for designing the classes in the test script.
  -----------------
  -Advantages of POM --> low maintenance,easy readability, no duplicity, reusability, reliability, avoid stale exception
  -POM strictly follows encapsulation and abstraction (data members-->private, initialize all data members within the constructor with public access specifier, utilize data members within the methods with access specifier public)
  -Number of data members in POM class = number of elements on webpage(test class-->WebDriver related, POM class-->WebElement related)
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.FindBy;
import org.openqa.selenium.support.PageFactory;

public class LoginPage {

    private WebDriver driver;

    @FindBy(id = "username")
    private WebElement usernameTxt;

    @FindBy(id = "password")
    private WebElement passwordTxt;

    public LoginPage(WebDriver driver) {
        this.driver = driver;
        PageFactory.initElements(driver, this);
    }

    public void enterUsername(String user) {
        usernameTxt.clear();
        usernameTxt.sendKeys(user);
    }

    public void enterPassword(String pass) {
        passwordTxt.clear();
        passwordTxt.sendKeys(pass);
    }
}
Note: PageFactory.initElements(driver, this);
Meaning:
- Initializes @FindBy WebElement fields in the current Page Object.
How it works:
- Scans this class (this) for @FindBy annotated variables.
- Creates WebElement proxies using the given locators.
- Actual element is located when you use it (lazy loading).
Parameters:
- driver -> WebDriver used to locate elements
- this   -> current Page Object containing @FindBy fields
Why needed:
- Without initElements(), @FindBy elements remain null
- Using them will throw NullPointerException

- initElements() initializes @FindBy fields by creating proxy objects.
- It usually does NOT immediately search the DOM for those elements.(So typically, no NoSuchElementException is thrown at init time.)
- When you perform an action on the WebElement (click/sendKeys/getText),Selenium then tries to locate the element using the @FindBy locator.
- If the element is not present at that time, it will throw an exception such as NoSuchElementException (or TimeoutException if you used an explicit wait).
Note:- This “search on use” is called lazy loading (proxy behavior).

--TestNg Listeners: Listeners are interfaces in TestNG that allow you to listen to events in the test execution life cycle, like test start, test success, test failure, skipped tests, etc.
  ----------------
They are very useful for reporting, logging, retry logic, screenshot capture on failure, etc.  
| Question                                   | Answer                                          |
| ------------------------------------------ | ----------------------------------------------- |
| What is a listener in TestNG?              | An interface that listens to test/suite events. |
| Most used listener?                        | `ITestListener` for test methods.               |
| Difference between `@Listeners` and XML?   | Annotation → per class; XML → global for suite. |
| Can we capture screenshot using listeners? | ✅ Yes, in `onTestFailure`.                      |
| How to retry failed tests?                 | Implement `IRetryAnalyzer`.                     |

| Listener                 | Description                                                        |
| ------------------------ | ------------------------------------------------------------------ |
| `ITestListener`          | Monitors **test method events** (start, success, fail, skip, etc.) |
| `ISuiteListener`         | Monitors **suite-level events** (suite start/end)                  |
| `IInvokedMethodListener` | Monitors **every method invocation** (before/after method)         |
| `IExecutionListener`     | Monitors **whole TestNG execution** (start/end)                    |
| `IRetryAnalyzer`         | Allows **retrying failed tests** automatically                     |
| `IReporter`              | Generates **custom reports** after execution                       |
| `ITestNGListener`        | Marker interface for all TestNG listeners                          |

import org.testng.ITestContext;
import org.testng.ITestListener;
import org.testng.ITestResult;

public class ListenerExample implements ITestListener {

    @Override
    public void onTestStart(ITestResult result) {
        System.out.println("Test Started: " + result.getName());
    }

    @Override
    public void onTestSuccess(ITestResult result) {
        System.out.println("Test Passed: " + result.getName());
    }

    @Override
    public void onTestFailure(ITestResult result) {
        System.out.println("Test Failed: " + result.getName());
        // You can capture screenshot here for Selenium
    }

    @Override
    public void onTestSkipped(ITestResult result) {
        System.out.println("Test Skipped: " + result.getName());
    }

    @Override
    public void onStart(ITestContext context) {
        System.out.println("Test Started: " + context.getName());
    }

    @Override
    public void onFinish(ITestContext context) {
        System.out.println("Test Finished: " + context.getName());
    }
}

--Retry Failed Test
import org.testng.IRetryAnalyzer;
import org.testng.ITestResult;

public class RetryFailedTests implements IRetryAnalyzer {

    int retryCount = 0;
    int maxRetryCount = 2;

    @Override
    public boolean retry(ITestResult result) {
        if (retryCount < maxRetryCount) {
            retryCount++;
            return true; // retry test
        }
        return false;
    }
}

@Test(retryAnalyzer = RetryFailedTests.class)
public void flakyTest() {
    System.out.println("Executing flaky test");
    throw new RuntimeException("Failing test intentionally");
}

--Data Parameterization from Excel file: using apache poi file, which has WorkbookFactory class(contains static method create()-->pass reference of the FileInputStream---> return Workbook instance)
  -------------------------------------
using Workbook reference, we call getSheet(sheet number) and so on..
import java.io.FileInputStream;
import org.apache.poi.ss.usermodel.*;

public class ExcelReadExample {

    public static void main(String[] args) throws Exception {

        // 1️⃣ Create InputStream for the Excel file
        FileInputStream file = new FileInputStream("TestData.xlsx");

        // 2️⃣ Create Workbook reference
        Workbook workbook = WorkbookFactory.create(file); // handles .xls & .xlsx

        // 3️⃣ Get sheet by index or name
        Sheet sheet = workbook.getSheetAt(0);  // first sheet
        // Sheet sheet = workbook.getSheet("LoginData"); // by name

        // 4️⃣ Iterate rows and cells
        for (Row row : sheet) {
            for (Cell cell : row) {
                switch (cell.getCellType()) {
                    case STRING:
                        System.out.print(cell.getStringCellValue() + "\t");
                        break;
                    case NUMERIC:
                        System.out.print(cell.getNumericCellValue() + "\t");
                        break;
                    case BOOLEAN:
                        System.out.print(cell.getBooleanCellValue() + "\t");
                        break;
                    default:
                        System.out.print(" \t");
                }
            }
            System.out.println();
        }

        // 5️⃣ Close workbook and stream
        workbook.close();
        file.close();
    }
}

import java.io.FileInputStream;
import java.io.IOException;
import java.util.Properties;

public class ConfigReader {

    private Properties properties;

    // Constructor loads the property file
    public ConfigReader() {
        try {
            FileInputStream fis = new FileInputStream("src/test/resources/config.properties");
            properties = new Properties();
            properties.load(fis);
            fis.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    // Method to get property value by key
    public String getProperty(String key) {
        return properties.getProperty(key);
    }
}

--How to handle validation: TestNG Assertions -->Assert/Hard Assert,Soft Assert
  ------------------------
| Feature                                | Hard Assert (`org.testng.Assert`)                                      | Soft Assert (`org.testng.asserts.SoftAssert`)                                                                                  |
| -------------------------------------- | -----------------------------------------------------------------------| -------------------------------------------------------------------------------------------------------------------------------|
| **Definition**                         | Immediately fails the test and stops execution if assertion fails      | Allows test to continue even if assertion fails; failures reported at the end with `assertAll()`                               |
| **Stops Execution on Failure?**        | ✅ Yes                                                                 | ❌ No, continues execution                                                                                                     |
| **Reports Failures**                   | ❌ Only the first failure                                              | ✅ All failures are reported when `assertAll()` is called                                                                       |
| **Use Case**                           | Critical validations, e.g., page not loading                           | Multiple validations in one test, e.g., form fields                                                                              |
| **Optional Message Support**           | ✅ Can pass custom message as last argument                            | ✅ Can pass custom message as last argument                                                                                      |
| **Example 1: Basic Check**             | `Assert.assertEquals(driver.getTitle(), "Home Page");`                 | `soft.assertEquals(driver.getTitle(), "Home Page");`                                                                              |
| **Example 2: Multiple Checks in Test** | ❌ Stops at first failure:  `Assert.assertTrue(element.isDisplayed());`| ✅ Continues for all checks: `soft.assertTrue(element1.isDisplayed());``soft.assertTrue(element2.isDisplayed());`soft.assertAll();|
| **Selenium Example**                   | Stop test if login fails                                                | Check multiple elements, fields, or links in the same test                                                                       |
| **Interview One-liner**                | Stops test immediately on assertion failure                             | Collects all assertion failures and reports at the end                                                                           |

| Method                         | Hard Assert (`Assert`)                              | Soft Assert (`SoftAssert`)                        | Description                                               |
| ------------------------------ | --------------------------------------------------- | ------------------------------------------------- | --------------------------------------------------------- |
| `assertEquals`                 | `Assert.assertEquals(actual, expected)`             | `soft.assertEquals(actual, expected)`             | Checks if actual equals expected                          |
| `assertEquals` with message    | `Assert.assertEquals(actual, expected, message)`    | `soft.assertEquals(actual, expected, message)`    | Same, with custom failure message                         |
| `assertNotEquals`              | `Assert.assertNotEquals(actual, expected)`          | `soft.assertNotEquals(actual, expected)`          | Checks if actual does NOT equal expected                  |
| `assertNotEquals` with message | `Assert.assertNotEquals(actual, expected, message)` | `soft.assertNotEquals(actual, expected, message)` | Same, with custom message                                 |
| `assertTrue`                   | `Assert.assertTrue(condition)`                      | `soft.assertTrue(condition)`                      | Asserts condition is true                                 |
| `assertTrue` with message      | `Assert.assertTrue(condition, message)`             | `soft.assertTrue(condition, message)`             | Same, with custom message                                 |
| `assertFalse`                  | `Assert.assertFalse(condition)`                     | `soft.assertFalse(condition)`                     | Asserts condition is false                                |
| `assertFalse` with message     | `Assert.assertFalse(condition, message)`            | `soft.assertFalse(condition, message)`            | Same, with custom message                                 |
| `assertNull`                   | `Assert.assertNull(object)`                         | `soft.assertNull(object)`                         | Asserts object is null                                    |
| `assertNull` with message      | `Assert.assertNull(object, message)`                | `soft.assertNull(object, message)`                | Same, with custom message                                 |
| `assertNotNull`                | `Assert.assertNotNull(object)`                      | `soft.assertNotNull(object)`                      | Asserts object is not null                                |
| `assertNotNull` with message   | `Assert.assertNotNull(object, message)`             | `soft.assertNotNull(object, message)`             | Same, with custom message                                 |
| `fail`                         | `Assert.fail()`                                     | `soft.fail()`                                     | Immediately marks test as failed                          |
| `fail` with message            | `Assert.fail(message)`                              | `soft.fail(message)`                              | Same, with custom message                                 |
| —                              | —                                                   | `soft.assertAll()`                                | Reports all collected failures (mandatory for SoftAssert) |
Note: For hard assert --> we have static methods, for soft assert, we have to create object of SoftAssert class

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.remote.RemoteWebDriver;
import org.openqa.selenium.remote.DesiredCapabilities;
import java.net.URL;

public class GridTest {
    public static void main(String[] args) throws Exception {

        // Hub URL
        URL hubUrl = new URL("http://localhost:4444");

        // Desired Browser
        DesiredCapabilities caps = new DesiredCapabilities();
        caps.setBrowserName("chrome");

        // RemoteWebDriver connects test to Grid Node
        WebDriver driver = new RemoteWebDriver(hubUrl, caps);

        driver.get("https://example.com");
        System.out.println("Title: " + driver.getTitle());
        driver.quit();
    }
}
