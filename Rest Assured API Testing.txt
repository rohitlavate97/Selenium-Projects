                     WHAT IS A REST API
================================================================================

+--------------------+                                   +--------------------+
|                    |                                   |                    |
|       CLIENT       |                                   |       SERVER       |
|   (Browser / App)  |                                   |     (Backend)      |
|                    |                                   |                    |
+--------------------+                                   +--------------------+
          |                                                           |
          |                                                           |
          |   HTTP REQUEST                                           |
          |   ---------------------------------------------------->  |
          |                                                           |
          |   METHODS:                                               |
          |     • GET                                                 |
          |     • POST                                                |
          |     • PUT                                                 |
          |     • DELETE                                              |
          |                                                           |
          |   URL / ENDPOINTS                                        |
          |     • /surveys                                           |
          |     • /surveys/123                                       |
          |     • /surveys/123/resp                                  |
          |                                                           |
          |                                                           |
          |                           PROCESS REQUEST                 |
          |                     (Business Logic + Database)           |
          |                                                           |
          |   JSON RESPONSE                                          |
          |   <----------------------------------------------------  |
          |                                                           |
          |   {                                                       |
          |     "survey_id"  : 123,                                   |
          |     "score"      : 9,                                     |
          |     "message"    : "amaze ...",                           |
          |     "response_id": 4                                      |
          |   }                                                       |
          |                                                           |
+--------------------+                                   +--------------------+


Client (App / Browser)
        |
        |  Request (GET / POST)
        ↓
      API
        |
        |  Logic + Validation
        ↓
   Server / Database
        |
        |  Data
        ↑
      API
        |
        |  JSON Response
        ↓
Client

REST API: Light weight protocols(Easy to build and maintain)
SOAP Services: So many conditons and restriction
Base URL or Endpoint: Address where API is hosted on the server

HTTP Methods used to communicate with Rest API's are:
 GET:   Used to extract information from the given server using a given URI, no payload/Body required(BODY is the containerPAYLOAD is the data inside the container)
        To input data in GET, use Query parameter
 POST:  A POST Request is used to send data to the server using Form parameters/Body payload
 PUT:   Updating/Replace all current representation of the target resource with the uploaded content
 DELETE:Remove all current Representations of the target resource given by a URI
 
-Resources represent API/Collection which can be accessed from the server 
  www.google.com/maps  --> www.google.com is server(Place where all your api's stored i.e Basic URI) + /maps is resource(which help to tie up to map api)
  There are few more details which are optional, depends upon how api is designed.
  
-Path Parameter--> Are variable parts of a URL path. They are typically used to point specific resource within collection, such as a user identified by ID
                   eg: https://www.google.com/images/112233
				       https://www.google.com/search?q=rest
-Query Parameter-->Used to sort/filter the resources, identified with '?'
                   eg: https://amazon.com/orders?sort_by=2/20/2020   --->sort_by=2/20/2020 this is the query
-Header/cookies-->Headers represent the meta-data associated with API request and response.(Additional details to process the request)
                  eg: Autorization details
				  
End Point Request URL constructed as below--> Base_URL/Resource/(Query_params/Path_params)

--Given–When–Then is a simple way to write test cases in human-readable steps.
✅ Given: This method accepts all the input we need to submit for API.
Precondition / Setup
What is already true before the action?
Example: Base URI set, headers set, payload prepared, user is logged in.
✅ When: This method will hit and submit API
Action
What you do / what request you send.
Example: Send a POST request to add a place.

✅ Then: This method validate the response
Expected Result / Verification
What you validate after action.
Example: Status code is 200, response has place_id, message is OK.

Note: User JSON to Java String Converter for body(https://dadroit.com/json-to-string/)

--Understanding structure of complex Json and ites array Notation:
------------------------------------------------------------------
{
  "dashboard": {
    "purchaseAmount": 910,
    "website": "rahulshettyacademy.com"
  },
  "courses": [
    {
      "title": "selenium python",
      "price": 50,
      "copies": 6
    },
    {
      "title": "cypress",
      "price": 40,
      "copies": 4
    },
    {
      "title": "RPA",
      "price": 45,
      "copies": 10
    }
  ]
}

ROOT
 ├── dashboard (object)
 │     ├── purchaseAmount
 │     └── website
 │
 └── courses (array)
       ├── [0] object
       ├── [1] object
       └── [2] object

OBJECT {}  → access by key
ARRAY  []  → access by index (0,1,2...)

START from ROOT {
1. Identify top-level keys:
   → dashboard (OBJECT)
   → courses (ARRAY)
--------------------------------------------------
2. Traverse dashboard (OBJECT):
   → Go inside "dashboard"
   → Read purchaseAmount = 910
   → Read website = rahulshettyacademy.com
--------------------------------------------------

3. Traverse courses (ARRAY):
   → Go inside "courses"
   → It contains list of objects → use index

   → Index 0:
        title = selenium python
        price = 50
        copies = 6

   → Index 1:
        title = cypress
        price = 40
        copies = 4

   → Index 2:
        title = RPA
        price = 45
        copies = 10
--------------------------------------------------

   → Move one object at a time (0 → 1 → 2)

import io.restassured.path.json.JsonPath;

public class CourseParsing {

    public static void main(String[] args) {

        String response = "{\n" +
                "  \"dashboard\": {\n" +
                "    \"purchaseAmount\": 910,\n" +
                "    \"website\": \"rahulshettyacademy.com\"\n" +
                "  },\n" +
                "  \"courses\": [\n" +
                "    {\"title\": \"selenium python\", \"price\": 50, \"copies\": 6},\n" +
                "    {\"title\": \"cypress\", \"price\": 40, \"copies\": 4},\n" +
                "    {\"title\": \"RPA\", \"price\": 45, \"copies\": 10}\n" +
                "  ]\n" +
                "}";

        JsonPath js = new JsonPath(response);

        // 1) Print number of courses returned by API
        int courseCount = js.getInt("courses.size()");
        System.out.println("Number of courses: " + courseCount);

        // 2) Print purchase amount
        int purchaseAmount = js.getInt("dashboard.purchaseAmount");
        System.out.println("Purchase Amount: " + purchaseAmount);

        // 3) Print title of the first course
        String firstTitle = js.getString("courses[0].title");
        System.out.println("First course title: " + firstTitle);

        // 4) Print all course titles and their respective prices
        System.out.println("\nAll courses (Title -> Price):");
        for (int i = 0; i < courseCount; i++) {
            String title = js.getString("courses[" + i + "].title");
            int price = js.getInt("courses[" + i + "].price");
            System.out.println(title + " -> " + price);
        }

        // 5) Print number of copies sold by RPA course
        int rpaCopies = 0;
        for (int i = 0; i < courseCount; i++) {
            String title = js.getString("courses[" + i + "].title");
            if (title.equalsIgnoreCase("RPA")) {
                rpaCopies = js.getInt("courses[" + i + "].copies");
                break;
            }
        }
        System.out.println("\nCopies sold by RPA: " + rpaCopies);

        // 6) Verify sum of all course amounts (price * copies) matches purchase amount
        int totalRevenue = 0;
        for (int i = 0; i < courseCount; i++) {
            int price = js.getInt("courses[" + i + "].price");
            int copies = js.getInt("courses[" + i + "].copies");
            totalRevenue += price * copies;
        }

        System.out.println("Total revenue (price * copies): " + totalRevenue);

        if (totalRevenue == purchaseAmount) {
            System.out.println("✅ Verified: Total revenue matches purchase amount");
        } else {
            System.out.println("❌ Not matched: Total revenue != purchase amount");
        }
    }
}

public class XmlTraverseExample {

    public static void main(String[] args) {

        String xml = "<root>\n" +
                "    <dashboard>\n" +
                "        <purchaseAmount>910</purchaseAmount>\n" +
                "        <website>rahulshettyacademy.com</website>\n" +
                "    </dashboard>\n" +
                "    <courses>\n" +
                "        <course>\n" +
                "            <title>selenium python</title>\n" +
                "            <price>50</price>\n" +
                "            <copies>6</copies>\n" +
                "        </course>\n" +
                "        <course>\n" +
                "            <title>cypress</title>\n" +
                "            <price>40</price>\n" +
                "            <copies>4</copies>\n" +
                "        </course>\n" +
                "        <course>\n" +
                "            <title>RPA</title>\n" +
                "            <price>45</price>\n" +
                "            <copies>10</copies>\n" +
                "        </course>\n" +
                "    </courses>\n" +
                "</root>";

        // 🔹 1. Dashboard values

        String website = xp.getString("root.dashboard.website");

        System.out.println(purchaseAmount);

        // 🔹 2. Count courses
        int count = xp.getList("root.courses.course").size();

        // 🔹 3. Loop through each course
        int total = 0;

        for (int i = 0; i < count; i++) {

            String title = xp.getString("root.courses.course[" + i + "].title");
            int price = xp.getInt("root.courses.course[" + i + "].price");
            int copies = xp.getInt("root.courses.course[" + i + "].copies");

            total += price * copies;

            if (title.equals("RPA")) {
                System.out.println("Found RPA course");
            }
        }

        // 🔹 4. Validation
        System.out.println("Total = " + total);
        System.out.println("Matches = " + (total == purchaseAmount));
    }

header("X-Atlassian-Token", "no-check") is used to bypass Atlassian’s XSRF/CSRF protection checks for requests that may be treated as “browser-style” requests (especially when you authenticate using session cookies like JSESSIONID).
Why it’s needed for session cookie
When you authenticate with cookies, Jira treats your request more like a browser session. For some POST/PUT/DELETE actions, Jira may enforce CSRF/XSRF protection and reject the request unless you either:
send a valid XSRF token, or explicitly tell Jira to skip the check using X-Atlassian-Token: no-check.
So this header helps prevent errors like: 403 Forbidden

--Handling Google/Facebook OAuth 2.0 Authentication Grant Types:
----------------------------------------------------------------
-OAuth 2.0 -> Industry standard protocol for authorization, it comes with multiple grant-types
-Authorization Code (secure web/mobile apps), Client Credentials (machine-to-machine) are the most commonly used grant types for OAuth(99% used)

--Authorization code Grant Type flow:
-------------------------------------
User/Browser        Client App                 Authorization Server         Resource Server(API)
    |                 |                                 |                        |
    |--- (1) GET /authorize?response_type=code -------->|                        |
    |                 |                                 |                        |
    |<-- login + consent UI ----------------------------|                        |
    |                 |                                 |                        |
    |--- (3) redirect to redirect_uri?code=...&state=... --> Client App         |
    |                 |                                 |                        |
    |                 |--- (4) POST /token (code, verifier/secret) ------------>|
    |                 |<-- (5) access_token (+ refresh_token) ------------------|
    |                 |--- (6) GET /api  Authorization: Bearer access_token --->|
    |                 |<-- protected data --------------------------------------|

Authorization Code Grant is the most common OAuth 2.0 login/authorization flow. It’s designed so the browser only carries a short-lived “code”, and the real tokens are fetched server-to-server (or with PKCE for public clients).
1. **Redirect to /authorize:** Browser → Authorization Server with `response_type=code, client_id, redirect_uri, scope, state, (PKCE) code_challenge + S256`.
2. **Login + consent:** User authenticates and approves requested scopes on the Authorization Server.
3. **Get auth code:** Authorization Server → Browser → `redirect_uri` with `code=...` and `state=...` (must match).
4. **Exchange code for tokens:** Client → `/token` with `grant_type=authorization_code, code, redirect_uri, client_id, (client_secret if confidential), (PKCE) code_verifier`.
5. **Receive tokens:** Authorization Server → Client with `access_token, token_type=Bearer, expires_in, (optional) refresh_token, (optional OIDC) id_token`.
6. **Call API:** Client → Resource Server with header `Authorization: Bearer <access_token>`.

                .contentType(ContentType.URLENC)
                .formParam("client_id", clientId)
                .formParam("client_secret", clientSecret)
                .formParam("grant_type", "client_credentials")
                .formParam("scope", "create")
            .when()
                .post("/oauthapi/oauth2/resourceOwner/token")

                .statusCode(200)
                .extract().asString();

        Assert.assertEquals((int) js.getInt("expires_in"), 3600);
        Assert.assertNotNull(js.getString("refresh_token"));
        Assert.assertNotNull(js.getString("access_token"));

        return js.getString("access_token");
    }

HTTP STATUS CODES (Quick Notes)

CATEGORIES
1xx = Informational
2xx = Success
3xx = Redirection
4xx = Client Error (request issue)
5xx = Server Error (server issue)

1xx INFORMATIONAL
100 Continue
101 Switching Protocols

2xx SUCCESS
200 OK (success)
201 Created (resource created)
202 Accepted (processing later)
204 No Content (success, no body)
206 Partial Content (partial response)

3xx REDIRECTION
301 Moved Permanently
302 Found (temporary redirect)
304 Not Modified (cache)
307 Temporary Redirect (method unchanged)
308 Permanent Redirect (method unchanged)

4xx CLIENT ERROR
400 Bad Request (invalid request)
401 Unauthorized (missing/invalid authentication)
403 Forbidden (authenticated but not allowed)
404 Not Found (endpoint/resource not found)
405 Method Not Allowed (wrong HTTP method)
408 Request Timeout
409 Conflict (duplicate/constraint conflict)

412 Precondition Failed (ETag/If-Match failure)
413 Payload Too Large

429 Too Many Requests (rate limited)

5xx SERVER ERROR
500 Internal Server Error
501 Not Implemented
502 Bad Gateway
503 Service Unavailable
504 Gateway Timeout

-SERIALIZATION & DESERIALIZATION in Rest Assured (POJO Based)
------------------------------------------------------------
SERIALIZATION
------------------------------------------------------------
Meaning:
- Converting a Java Object (POJO) into Request Body (Payload)
  (Usually JSON, sometimes XML)

Example:
given()
  .contentType(ContentType.JSON)
  .body(javaObject);   // Rest Assured converts POJO -> JSON at runtime

------------------------------------------------------------
DESERIALIZATION
------------------------------------------------------------
Meaning:
- Converting Response Body (JSON/XML) back into a Java Object (POJO)

Example:
ResponsePojo res =
given()
.when()
  .get("/endpoint")
.then()
  .extract().as(ResponsePojo.class);  // JSON -> POJO

------------------------------------------------------------
ADVANTAGES (Why POJO?)
------------------------------------------------------------
- Easy to build payloads (no manual JSON strings)
- Easy to parse response values using getters
- Cleaner, reusable, maintainable automation framework
- Strong typing + fewer parsing errors

------------------------------------------------------------
DESIGN APPROACH
------------------------------------------------------------
1) Create POJO classes based on Request/Response payload structure
2) Construct Java Object using POJO class + setters
3) Serialize POJO -> JSON for request
4) Deserialize JSON -> POJO for response

------------------------------------------------------------
REQUIRED LIBRARIES (Mappers)
------------------------------------------------------------
For JSON (any one in classpath):
- Jackson / Jackson2
- Gson
- Johnzon

For XML:
- JAXB

------------------------------------------------------------
SAMPLE POJO
------------------------------------------------------------
public class Message {
  private String message;

  public String getMessage() {
    return message;
  }

  public void setMessage(String message) {
    this.message = message;
  }
}

------------------------------------------------------------
SERIALIZATION EXAMPLE (Java Object -> JSON)
------------------------------------------------------------
1) Create POJO object
   Message message = new Message();
2) Set values
   message.setMessage("Hello");
3) Pass POJO to Rest Assured
   given()
     .contentType(ContentType.JSON)
     .body(message);
4) Rest Assured uses mapper (Jackson/Gson) to convert POJO -> JSON
   This is SERIALIZATION

--OAuth 2.0 Automation with client credentials grant-type:
----------------------------------------------------------
WHEN TO USE .contentType(ContentType.URLENC)  (application/x-www-form-urlencoded)--> .contentType(ContentType.URLENC)   //similar to .header("Content-Type", "application/x-www-form-urlencoded")
USE URLENC WHEN:
1) OAuth token APIs (most common)
   - /token endpoint expects:
     grant_type, client_id, client_secret, code, refresh_token
   - Body format: key=value&key2=value2
   - Postman: Body -> x-www-form-urlencoded

   Example:
   given()
     .contentType(ContentType.URLENC)
     .formParam("grant_type","client_credentials")
     .formParam("client_id","...")
     .formParam("client_secret","...")
   .when()
     .post("/token");

2) Any API that explicitly says:
   - Content-Type: application/x-www-form-urlencoded
   - "Send as form-urlencoded"

DO NOT USE URLENC WHEN:
1) API expects JSON payload
   - Use: .contentType(ContentType.JSON)
   - Use: .body("{...}")

   Example:
   given()
     .contentType(ContentType.JSON)
     .body("{\"name\":\"Sujal\"}")
   .when()
     .post("/users");

2) File upload / multipart
   - Use: multipart/form-data
   - Use: .multiPart(...)

   Example:
   given()
     .multiPart("file", new File("a.png"))
   .when()
     .post("/upload");

EASY RULE:
- Token / login-form style data -> URLENC
- REST APIs with JSON -> JSON
- File upload -> multipart

package com.alchemist.framework.config;

import java.io.InputStream;
import java.util.Properties;

public class ConfigManager {

    private static final Properties configProps = new Properties();
    private static final Properties secretProps = new Properties();

    static {
        // Load config.properties (required)
        try (InputStream is = ConfigManager.class.getClassLoader().getResourceAsStream("config.properties")) {
            if (is == null) throw new RuntimeException("config.properties not found in src/main/resources");
            configProps.load(is);
        } catch (Exception e) {
            throw new RuntimeException("Failed to load config.properties", e);
        }

        // Load secrets.properties (optional but recommended for local)
        try (InputStream is = ConfigManager.class.getClassLoader().getResourceAsStream("secrets.properties")) {
            if (is != null) {
                secretProps.load(is);
            }
        } catch (Exception e) {
            throw new RuntimeException("Failed to load secrets.properties", e);
        }
    }

    private ConfigManager() {}

    public static String baseUrl() { return configProps.getProperty("baseUrl"); }
    public static String scope() { return configProps.getProperty("scope"); }
    public static String tokenPath() { return configProps.getProperty("tokenPath"); }
    public static String courseDetailsPath() { return configProps.getProperty("courseDetailsPath"); }

    // Priority: ENV -> secrets.properties
    public static String clientId() {
        String env = System.getenv("RSA_CLIENT_ID");
        if (env != null && !env.isBlank()) return env;

        String v = secretProps.getProperty("clientId");
        if (v == null || v.isBlank()) throw new IllegalStateException("clientId missing (set RSA_CLIENT_ID env OR secrets.properties)");
        return v;
    }

    public static String clientSecret() {
        String env = System.getenv("RSA_CLIENT_SECRET");
        if (env != null && !env.isBlank()) return env;

        String v = secretProps.getProperty("clientSecret");
        if (v == null || v.isBlank()) throw new IllegalStateException("clientSecret missing (set RSA_CLIENT_SECRET env OR secrets.properties)");
        return v;
    }
}

package com.alchemist.framework.utils;

import com.alchemist.framework.clients.OAuthClient;
import com.alchemist.framework.models.TokenResponse;

public class TokenManager {

    private TokenManager() {}

    private static String token;
    private static long expiryTimeMs;

    public static synchronized String getToken() {
        long now = System.currentTimeMillis();

        if (token == null || now >= expiryTimeMs) {
            TokenResponse tr = new OAuthClient().generateToken();
            token = tr.access_token;
            expiryTimeMs = now + (tr.expires_in - 30) * 1000L; // 30 sec buffer
        }
        return token;
    }
}

--Understand Request and Response Spec Builder in Rest Assured:
---------------------------------------------------------------
REQUESTSPECBUILDER & RESPONSESPECBUILDER (Rest Assured) 
========================================================

1) RequestSpecBuilder
---------------------
Meaning:
- Used to create a reusable "RequestSpecification"
- Common request settings that you repeat in every API call

Common things to keep in Request Spec:
- baseUri / basePath
- default query params (ex: key=qaclick123)
- default headers
- Content-Type
- authentication
- logging filters

Example:
RequestSpecification reqSpec = new RequestSpecBuilder()
  .setBaseUri("https://rahulshettyacademy.com")
  .addQueryParam("key","qaclick123")
  .setContentType(ContentType.JSON)
  .addHeader("Accept","application/json")
  .build();

Usage:
given()
  .spec(reqSpec)
  .body(payload)
.when()
  .post("/maps/api/place/add/json");


2) ResponseSpecBuilder
----------------------
Meaning:
- Used to create a reusable "ResponseSpecification"
- Common validations you apply to responses

Common things to keep in Response Spec:
- expected status code (200/201/401 etc.)
- expected response content type (JSON/XML)
- expected headers
- response time limit

Example:
ResponseSpecification resSpec = new ResponseSpecBuilder()
  .expectStatusCode(200)
  .expectContentType(ContentType.JSON)
  .build();

Usage:
given()
  .spec(reqSpec)
.when()
  .get("/oauthapi/getCourseDetails")
.then()
  .spec(resSpec);


WHY USE THEM (Framework):
- Removes duplicate code
- Makes tests clean and readable
- Easy to change baseUrl/headers in one place
- Easy to create multiple specs (200, 201, 401, etc.)

package com.alchemist.utils;

import org.apache.poi.ss.usermodel.*;
import org.apache.poi.xssf.usermodel.XSSFWorkbook;

import java.io.FileInputStream;
import java.util.ArrayList;
import java.util.List;

public class ExcelUtils {

    private ExcelUtils(){}

    public static Object[][] readBooksFromFile(String filePath, String sheetName) {
        try (FileInputStream fis = new FileInputStream(filePath);
             Workbook wb = new XSSFWorkbook(fis)) {

            Sheet sheet = wb.getSheet(sheetName);
            if (sheet == null) throw new RuntimeException("Sheet not found: " + sheetName);

            DataFormatter fmt = new DataFormatter();
            List<Object[]> rows = new ArrayList<>();

            for (int r = 1; r <= sheet.getLastRowNum(); r++) {
                Row row = sheet.getRow(r);
                if (row == null) continue;

                String run = fmt.formatCellValue(row.getCell(0)).trim();
                if (!run.equalsIgnoreCase("Y")) continue;

                String isbn = fmt.formatCellValue(row.getCell(1)).trim();
                String aisle = fmt.formatCellValue(row.getCell(2)).trim();

                rows.add(new Object[]{isbn, aisle});
            }

            return rows.toArray(new Object[0][0]);

        } catch (Exception e) {
            throw new RuntimeException("Failed to read Excel file: " + filePath, e);
        }
    }
}

import java.util.ArrayList;
import java.util.List;

public class ExcelUtils {

    private ExcelUtils(){}

    public static Object[][] readBooksFromResource(String excelResourceName, String sheetName) {
        try (InputStream is = ExcelUtils.class.getClassLoader().getResourceAsStream(excelResourceName)) {
            if (is == null) throw new RuntimeException("Excel not found: " + excelResourceName);

            Workbook wb = new XSSFWorkbook(is);
            Sheet sheet = wb.getSheet(sheetName);
            if (sheet == null) {
                wb.close();
                throw new RuntimeException("Sheet not found: " + sheetName);
            }

            DataFormatter fmt = new DataFormatter();     //✅ DataFormatter avoids that problem and gives you a safe String output.
            int lastRow = sheet.getLastRowNum();

            List<Object[]> rows = new ArrayList<>();

            for (int r = 1; r <= lastRow; r++) {
                Row row = sheet.getRow(r);
                if (row == null) continue;

                String run = fmt.formatCellValue(row.getCell(0)).trim();
                if (!run.equalsIgnoreCase("Y")) continue;

                String isbn = fmt.formatCellValue(row.getCell(1)).trim();
                String aisle = fmt.formatCellValue(row.getCell(2)).trim();

                rows.add(new Object[]{isbn, aisle});       //Object[] = one row of data, Object[][] = many rows (multiple test iterations)
            }

            wb.close();
            return rows.toArray(new Object[0][0]);

        } catch (Exception e) {
            throw new RuntimeException("Failed to read Excel: " + excelResourceName + " sheet: " + sheetName, e);
        }
    }
