WSDL(Web Services Definition Language): - A wsdl is an xml document that describes a web service.
                                        - Web Service = Collection of Operations.
										- Webservice reads your SOAP message, it will see particular operation and redirects to that specific thing.
										- For testing SOAP webservices, we get WSDL as contract
										e.g->www.dneonline.com/calculator.asmx -->Service description i.e contract(It is mentioned here, following operations are supported-->Add,Substract,Multiply,Divide)
										wsdl:binding ->Term which shows how many operations it supports
										wsdl:type ->What type of parameter operation is expecting
										-wsdl specifies the location of service and the methods of the service using these major elements
										
-SOAP message is an xml document which used to transmit data. Wsdl is an xml document which describes how to connect and make requests to your web service
Basically SOAP messages are the data you transmit, WSDL tells you what you can do and how to make the calls
SOAP is structure you apply to your message/data for transfer,WSDL are used only to determine how to make calls to the service in the 1st place.

 -fetch all properties in SOAP message as follows
 Synatx:
 <soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope" xmlns:typ="http://sample.com/reservation/guest/types">
   <soap:Header/>
   <soap:Body>
      <typ:addEmployee>
         <!--Optional:-->
         <typ:name>${#TestSuite#name}</typ:name>
         <!--Optional:-->
         <typ:id>${#Project#id}</typ:id>
         <!--Optional:-->
         <typ:Department>${Properties#Department}</typ:Department>    //${Properties#Department} -->As we have given name 'Properties' to test step, we can see this name here, name of the test step appear, not generic like others
         <!--Optional:-->
         <typ:age>${#TestCase#age}</typ:age>
      </typ:addEmployee>
   </soap:Body>
</soap:Envelope>
